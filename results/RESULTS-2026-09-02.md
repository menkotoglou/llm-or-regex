# Results, 2 Sep 2026 — what I could run without your API keys

**Machine:** Anthropic sandbox container (Linux x86_64, Python 3.12). Latency numbers are *shape*, not your slide: re-run `make local` on the laptop you will quote.
**Dataset:** `surge-1k` — Surge AI toxicity set (GitHub `surge-ai/toxicity`, 2022, 1,000 social-media comments, 501 toxic / 499 clean). Chosen because it is reachable from the sandbox (HF/Kaggle are not), held out from apc's training data, and labelled for *toxicity*, not profanity. Civil Comments stays the primary set; run it on your side.
**Arms:** `regex` (LDNOOBW, 403 words), `apc` 1.9.0, `own` (tf-idf + logistic regression on the product's own labels, 5-fold CV). No LLM arms: no keys here.

## Experiment 1 — accuracy on a held-out set

| arm | P | R | F1 | acc | tp / fp / fn / tn |
|---|---|---|---|---|---|
| regex | 0.873 | 0.248 | 0.386 | 0.605 | 124 / 18 / 377 / 480 |
| apc @0.5 | 0.931 | 0.481 | 0.634 | 0.722 | 241 / 18 / 260 / 480 |
| own (1,000 labels, CV) | 0.871 | 0.852 | **0.862** | 0.863 | — |
| regex OR apc | 0.910 | 0.503 | 0.648 | | |

apc threshold sweep: recall only reaches 0.72 at t=0.1, and precision has fallen to 0.79 by then. Moving the threshold does not fix this.

**What the errors are** (`results/errors/`):

- apc's 18 false positives are *profanity without hostility*: "so fucking cool", "Damn! This is actually really cool", "busy ass Saturday". The library answers "is there profanity?"; the product asks "is this toxic?".
- apc's 260 false negatives are *hostility without profanity*: "NEEDS THE GALLOWS", "Execute them all", "Why is trans community ruining everything", plus 2021–22 vocabulary the 2018-era corpus never saw ("Libturd", "Trumptards"), plus real-world obfuscation already in the data ("dumba$$es", "p u s s y"). Scores are 0.003–0.011: the model is not unsure, it is confidently wrong.
- A 20-line sklearn pipeline on 800 task-matched labels beats the 200k-sample pretrained package by 23 F1 points, at 1.3–1.6 ms per item. (5-fold CV on one small set is an in-distribution estimate; say so.)

## Experiment 7 — obfuscation (`scripts/make_obfuscation.py`)

124 toxic items where the word list fires; every match transformed; label unchanged by construction. Recall:

| transform | regex | apc |
|---|---|---|
| original | 100.0% | 91.1% |
| l33t (`fvck`, `$h17`) | 16.9% | 38.7% |
| spaced (`f u c k`) | 0.0% | 29.0% |
| homoglyph (Cyrillic а/е/о) | 20.2% | 41.1% |
| asterisk (`f**k`) | 0.0% | 29.0% |
| concatenated (`youfucking`) | 8.1% | 29.8% |

apc's ~29% floor is the hostile *context* still voting; the word itself is gone. Both classical arms collapse on the cheapest evasion a user can type. This is the LLM's slide to win; run the same file through the LLM arms.

## What this changes in the talk

1. **Accuracy ceiling is about labels, not model family.** The strongest honest line in the talk is now: *with 1,000 labels from your own product, a 20-line sklearn model beats the pretrained package by 23 F1 points, and probably competes with the small LLM at 1/10,000 of the cost.* The LLM's real edge is zero labels, obfuscation, and languages, not raw accuracy on your core distribution. Add `own` as a fifth arm on the summary slide.
2. **The confidence-band cascade does not rescue apc here.** Only ~11% of traffic sits in the (0.3, 0.7) band, but recall on the "confident" 89% is still 0.48, because the misses score 0.005. Routing on confidence only works when the cheap model answers the *same question* as the product. So Section 5's cheap stage should be `own`, not `apc`; then the band catches genuine uncertainty. Measure it: `make cascade` with `OWN` as the router (see the update doc).
3. **Drift has a face.** "Libturd" and "Trumptards" are not in a 2018 corpus. That is the drift-axis slide: a static model ages; a wordlist ages faster; an LLM is retrained for you but changes underneath you (experiment 4 measures that side).
4. **The obfuscation table is a slide as-is.** Six rows, two columns, zero explanation needed. Add the LLM columns and it becomes the "when to pay" slide.

## Addendum, 15 Sep — Experiment 9: identity-term false positives

115 innocuous sentences (23 identities × 5 templates, e.g. "Proud to be {} at this conference."), all clean.

| identity | regex | apc @0.5 | own (surge-1k labels) |
|---|---|---|---|
| queer | 0/5 | **4/5** (max 0.787) | 0/5 |
| gay | 0/5 | **2/5** (max 0.552) | 0/5 |
| lesbian, bisexual, trans, transgender, non-binary, straight, cisgender | 0/5 | 0/5 | 0/5 |
| Black | 0/5 | 0/5 | **1/5** ("My neighbour is Black and she is the kindest person I know", 0.555) |
| Muslim, Jewish, Christian, atheist, white, Asian, Latina, immigrant, disabled, deaf, autistic, old, young | 0/5 | 0/5 | 0/5 |

"Proud to be queer at this conference." → apc 0.594, flagged. "Proud to be straight at this conference." → 0.022.

The bag-of-words model learned that "queer" and "gay" co-occurred with toxicity in its 2017–18 training data (Wikipedia talk pages, Twitter), i.e. the word, not the intent. The task-matched `own` arm does not repeat that mistake but carries its own: one Black-identity sentence flagged, from 1,000 labels of 2022 US social-media comments. Every classical arm inherits the bias of its labels; the check belongs in CI, per release, with an allowlist for self-description. LLM columns: `make identity` after setting the model IDs.

Slide changes driven by this: new slide "The failure that silences people" in Section 3; the recall / miss examples on slides 8 and 10 replaced with non-political, non-identity hostility; drift tokens replaced with new-vocabulary profanity; the slur in issue #71 masked on the slide.
